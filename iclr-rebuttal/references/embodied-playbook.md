# 具身论文常见质疑：把回答变成证据

本页提供具身任务的实验和协议核查建议。需要参考作者如何回应时，从[统一案例库](case-library.md)选择涉及同一科学疑问的讨论，例如借统计学习案例判断小幅成功率差是否可靠。

## 记忆是否真的必要？

不要只说任务长。说明当前观察为什么不能决定下一步，哪条过去信息能消除歧义，以及它距离现在多少帧/秒。长时序、任务规划和部分可观测性不是同一概念。

可用证据：相似当前画面但所需动作不同的状态对；显式记忆任务；控制视觉输入与训练数据的 no-memory 对照；关键帧检索可视化；memory window 与任务依赖跨度的比较。

注意：注意力图说明相关线索被关注，不单独证明因果。仅有总体成功率不能排除额外参数、更多观测或动作 chunk 的贡献。MemoryVLA 用专门 benchmark 与 chunk 消融回应；MemER 用关键位置离开滑动窗口的例子解释任务需求。

## 收益是否只是 action chunking？

分清预测 horizon、每次执行的 action 数、推理调用频率、原始帧率与记忆采样频率。理想对照是在相同设置中交叉比较 memory on/off 与多个 chunk 长度，其他条件一致。

无法完成完整交叉实验时明确哪些因素未被隔离。不要把“在某几个任务缩短 chunk 后仍有效”写成“chunking 在任何任务都不能代替记忆”。

## 不同基线是否公平？

记录以下决定比较含义的条件，取相关项呈现：

| 维度 | 需核对内容 |
|---|---|
| 模型 | 方法名、版本、checkpoint、参数量、动作头 |
| 数据 | 预训练来源、私有数据、微调 demonstrations、更新步数 |
| 输入 | 前视/腕视、分辨率、RGB-D、机器人状态、历史长度 |
| 执行 | 动作空间、planner、闭环/开环、chunk、重规划频率 |
| 评估 | task split、环境版本、初态/种子、rollouts、成功判据 |
| 选择协议 | checkpoint/超参的选择集合、验证集、测试集使用方式 |

将“完整系统在同一任务的比较”与“隔离某模块的控制变量比较”分开。统一指标不意味着训练预算、观测信息或执行器可比。复现分数异常时先核实版本和预处理；未排除实现错误的 0% baseline 不能支持强优越性主张。

VLM4VLA 对官方 Pi0 checkpoint 与控制预训练条件的实现作了区分；Embodied-R1 追溯 OpenVLA 与 OpenVLA-OFT；ERA 的微调小模型与零样本大模型比较仍引发争议。

## 缺少基线或相关工作

先识别请求类型：

- **漏引用**：读相应工作，补正确引用，准确承认共性和差异。
- **概念比较**：按输入、表示、训练、记忆更新、输出接口、适用范围列对比。
- **实验比较**：尽量同数据、同输入和相近预算；若不可比，说明具体约束并限定主张。

替代性的 FIFO/long-context baseline 只能验证特定机制，不能未经实测声称等价于某完整方法或构成其性能上界。不能用“不同领域”“同期论文”“我们已有大量实验”回避实际问题。

## 新颖性与简单架构

明确哪些是现成模型、算法、代码框架；把新增部分具体化为训练目标、数据设计、记忆更新、接口或经验证的新发现。用去掉该部分的对照支持贡献。研究价值可以来自系统或数据，但不应虚构基础算法创新。

回答顺序：承认共性 → 精确定义新增项 → 对照/消融证据 → 修改贡献与引用。避免用大量形容词替代增量描述。MemER 的简单接口与部署结果获得部分 reviewer 认可；Embodied-R1 的创新争议未完全消失；ERA 说明完整回复并不能保证核心问题解决。

## 仿真、真机与泛化

区分四类结论：环境内未见初态、未见物体/指令、跨场景/视角、跨机器人形态。模型结构“兼容”新机器人不等于已经验证迁移；用真机图像训练也不等于真机闭环测试。

报告任务数、变体数和试验次数时分别命名，不能相互替代。少量 demo 视频仅为定性证据；小样本成功率需保留分母，不把一次成功写成稳健性证明。

若来不及做真机，说明仿真结果回答的有限问题，收缩标题/摘要/结论相关措辞。若新增真机，说明训练是否用真机数据、是否零样本、有哪些额外感知器/控制器。不要把新增真机实验当作已经消除所有数据和基线混杂。

## 延迟、吞吐与系统部署

至少在相关场景给出硬件、精度、上下文/记忆长度、batch、预热与测量范围。区分：

- 高层规划一次耗时与低层控制频率；
- 单次输出多步动作产生的吞吐与感知反馈频率；
- 模块显存与整个系统显存；
- GPU 计算延迟、感知/通信/执行延迟与 API 网络延迟。

例如一次预测 16 个动作所计算出的 Hz，不能直接写成同频率的闭环更新。MemER 的约 0.8 秒是高层预测层面的结果，并非低层每个控制动作的延迟。无需为所有稿件加入这些指标，但涉及“实时”“轻量”时应匹配其实际含义。

对“成本更低”，分解一次性数据生成/训练成本与每次部署成本。若要给摊销临界部署量，可用 N = 训练及生成成本 / (基线单次成本 − 本方法单次成本)，前提是计量单位、任务效果和比较条件可比且分母为正；缺测量就不给精确结论。

## 训练信息、标签质量与记忆标注

画清楚训练目标来源、推理输入、评估 oracle 的位置。模拟器状态可以是训练监督，也可能是测试特权信息，必须按实际接口回答。规则用于生成训练关键帧标签，不等于推理时依赖人工规则；反过来，若仍有人工干预，也要说明。

标注成本区分一次性规则编写、每任务设置、每轨迹标注、质量检查与 demo 采集成本。像 MemER 的“每任务约 5 分钟”不可被改写为完整数据集采集总成本。

## 内部一致性与数值审查

- 重算表内平均和增幅；核实宏平均/加权平均以及遗漏任务。
- 区分成功率百分点变化与相对百分比增长。
- 若报告 Pearson r 与 R²，核对定义；常规单自变量带截距最小二乘拟合有 R²=r²，其他定义要解释，不能为了“修正”直接改源数据。
- 分清 mean±SD、标准误、置信区间；不要把多个 checkpoint 的离散程度写成独立随机种子不确定性。
- 避免用相同测试集反复择优结果来证明无偏泛化；报告实际模型选择协议。
- 对多个 reviewer 使用同一实验登记表，防止“恢复只在 RL 出现”与“监督阶段已学会恢复”这类说法互相冲突。
- 发现来源数字矛盾时标记并回查；案例只是写作研究材料，不是可直接复制的实验数据库。
