# 返修与多智能体协作流程

用于完整 reviewer 回复、跨轮作者确认、独立分析与模拟审查，以及已授权的稿件同步。它是实践归纳，不是会议规则。团队规模、交付格式、颜色和页数遵循当前任务；单条澄清可以直接完成。

## 1. 建立所有参与者共享的事实依据

先读评审原文、当前正文和相关附录，再定位引用的表图及原始结果。旧对话和旧回复只作线索，不能替代当前文件。围绕真正影响主张的事实建立简短记录：

| 主张或比较对 | 可用结果及来源 | 已确认条件 | 未确认或冲突项 | 当前能支持的结论 |
|---|---|---|---|---|
| 模块 A 对比控制 B | 文件/表/实验记录/作者确认 | 数据、初始化、训练策略等相关项 | 仅列影响解释的缺项 | 受控因素效果或系统配置比较 |

把事实可信状态与实验完成状态分开。已得到结果不等于已写入稿件，作者确认某一比较对也不意味着整张表都受控。

向作者提问时说明哪个结论依赖答案，合并少量关键问题，并继续处理不依赖答案的部分。先查现有材料，再问作者，不重复问已确认事实。区分：

- **事实待确认**：已有实验，训练条件或统计口径尚不明确。
- **证据确实缺失**：材料和作者确认都不能提供区分关键替代解释的证据。
- **可选增强**：有助于扩大结论，但不是当前有限主张成立的必要条件。

作者补充事实后，应重组比较和结论，不只在旧草稿末尾追加一句。既不能维持已被排除的宽泛免责声明，也不能把新确认扩展到未涉及的设置。

## 2. 多智能体分工与独立性

用户要求多智能体，或争议复杂且并行审查有价值时，按可用工具和授权组织团队。独立性是任务与上下文隔离，不保证判断在统计意义上独立。工具不可用或不允许委派时，明确说明，不伪称进行了独立审查。

一种适用于复杂返修的分工如下，可合并角色或顺序执行：

| 角色 | 主要产出 | 边界 |
|---|---|---|
| 主智能体/协调者 | 统一事实记录、问题映射、最终判断与交付文件 | 负责裁决和整合，不以多数票替代证据 |
| 独立分析者 A、B | 各自的问题解释、回应方案、最强证据与尚存反例 | 首轮互不阅读对方结论，不预设“必须说服评审” |
| 模拟审稿者 | 对同一草稿逐项指出核心疑问是否得到回答 | 不凭拟人身份预测真实评分或录用 |
| 数值/文稿核查者（可选） | 统计复算、引用和跨文件一致性 | 不越权改实验事实或接管整篇写作 |

让独立分析者读取相同的原始材料、作者已确认事实、任务约束和输出要求。若工具支持，使用新上下文，而非把另一位分析者或主智能体的结论一起传入。若无法隔离，应如实限定“独立”的含义。多 reviewer 场景也可按 reviewer 分工，但共享统一实验记录。

建议首轮输出控制在以下内容：核心疑问、直接回答、证据及对应位置、替代解释、确切缺项、可删除的无关细节。无需每位分析者都先写一份冗长全文。

### 可复用的委派任务

**独立分析：**

> 阅读指定评审、当前稿件及作者确认记录。独立判断哪些主张已有证据、哪些仍有混杂，提出逐点回应方案。请给来源位置，区分必要补证与可选扩展。首轮不要读取其他分析者结论。仅给分析，不修改共享文件或向作者发送问题。

**模拟审查：**

> 根据原评审问题和提供的事实，审查这份回复。逐项给出“已回答、部分回答、未回答”及理由。对未解决项说明可由文字修复、已有实验条件确认还是新增证据解决，并说明与核心主张的关系。不要以必须接受或必须拒绝为目标，不添加未证实事实，不修改文件。

主智能体汇总提问，避免多个 agent 重复打断作者。默认由主智能体统一写文件；若分配编辑，明确各自文件或不重叠片段，再顺序整合。共享工作区中的并行全文改写容易覆盖有效修改。

## 3. 辩论与整合：只讨论有后果的分歧

首轮完成后，再向分析者共享彼此的具体分歧。协调者将分歧改写成可裁决的问题：

| 分歧 | 裁决依据 | 处理方式 |
|---|---|---|
| 某对照是否隔离目标因素 | 对比行和已确认训练条件 | 受控结论、配置级结论或向作者核实 |
| 是否必须增加实验 | 当前主张与替代解释能否被现有证据区分 | 最小补证，或收缩未支持的主张 |
| 某术语是否准确 | 操作定义、训练接口与可观察行为 | 明确定义或替换术语 |
| 某实现细节是否进入回复 | 省略后是否改变比较含义 | 必要条件留回复，其余放附录或省略 |

要求双方回答对方最强的异议，并给出新证据或逻辑依据。不要为表演“辩论”重复立场，不靠投票决定实验事实，不让 agent 自行补造数值以消除分歧。

优先检查已有结果能否组成所需对照。例如，完整系统同时改变模块和训练策略时，先查同训练策略下的模块变体。已有三种配置可能足以分别支持条件性增益，无需自动要求完整交叉实验。不能由这些差值推断未测设置、全局可加性或交互效应。

## 4. 起草与模拟审查闭环

先写审稿人能直接核查的草稿：结论、关键表格或论证、决定性条件、修改位置。写给评审的内容不含“作者需要补”“内部未通过”等工作备注。主回复聚焦背后的科学疑问，不变成实现细节清单。

把同一版本草稿交给模拟审稿者。首轮不附上另一位模拟审稿者的判断，也不提示“预期通过”。若用户要求“满意才通过”，把“通过”落实为原问题已被证据回答，而非必须获得接受票。

每轮将反馈分流：

| 反馈性质 | 下一步 |
|---|---|
| 表述、表格或比较行错误 | 用已核实事实修订，检查相邻结论 |
| 条件未确认，可能已有合适实验 | 向作者核实决定性缺项，保留有限结论 |
| 核心解释无法由现有证据区分 | 告诉作者最小所需实验及其区分的问题，或明确缩小主张 |
| 与原问题无关或超出有限主张的扩展 | 不作为硬性阻断项，可列为可选增强 |

协调者把需要返工的项目分派给原分析者或相应核查者，交接问题 ID、最新事实、争议理由和期望产出。各 agent 返回修订建议或负责片段，主智能体解决冲突后合并为同一版本，再交模拟审稿者复核。每轮只传播新增事实与相关差异，避免让各角色依据不同版本反复争论。

复审只检查已修改的争议及其连带影响，不把已解决问题无限重新打开。无需让全部 agent 每轮重读全文。

**停止条件：**核心疑问已有可核验回答，且没有新增实质性反例时交付。若剩余缺口确需作者数据或新实验，交付已完成部分并清楚列出缺项，不反复改写以争取“通过”。模拟结果只能称为内部审查判断，不能写成实际 reviewer 认可、已提分或录用保证。

## 5. 结果表与统计记录

一张表回答一个比较问题，或按已确认条件分组。通常先选必要的控制行，再决定是否展示完整消融。表内可列条件、均值、SD、已计算的 CI 和百分点差；指标、样本量、重复阶段放表注或附近一句，避免每格重复。

三类证据宜分清：跨方法的系统结果、隔离某因素的受控结果、跨对象/任务/传感器的迁移结果。缺失评估不填零，没有重复实验的结果不自行补 SD 或 CI。逐次计数通常放附录，回复保留足以判断的摘要。

重算规则见 [通用问题手册](general-playbook.md) 的统计部分。给多个 agent 或 reviewer 使用同一计算结果和版本，避免各自从舍入后的表格二次计算而产生分歧。

## 6. 同步稿件与文件交付

仅在用户授权的范围内写回文件。“先分析”“只给对话草稿”不包含修改论文的授权。已有明确编辑授权时，不重复请求确认。

- **最小改动**：在承载主张的位置补必要条件或纠正归因，保留可用原句。定义建立后，方法和实验回扣同一含义，避免反复重新定义。
- **主线一致**：回复不能是唯一解释关键创新或公平比较的位置。若已获稿件编辑授权，在正文明确核心机制和决定性条件，附录承载实现细节与完整记录。
- **数值依赖**：原始结果更新后，复查摘要、引言、主表、实验分析、结论、附录和各 reviewer 回复。均值、SD、CI、最佳结果粗体、差值及图内文字均可能受影响。
- **源文件与图稿**：文本搜索不足以发现 PDF/图片中的旧数值，检查相关图稿及其源文件；不要仅更新 caption 后声称图已同步。
- **版面核验**：按用户指定颜色标记变更，编译当前源文件并检查 PDF。若有正文上限，确认结论确实完整落在允许页内，区分正文与参考文献/附录。先精简冗余文字和调整合理排版，不随意压缩规定字号、边距或隐藏必要内容。
- **保持可核查**：核对表图编号和正文引用，避免把整段结论与证据跨回复帖拆散。多人编辑时只修改负责范围，交付前检查是否覆盖了他人修改。

最后交付所请求的英文回复或文件链接、简短变更清单和实际验证结果。若经过模拟审查，单独说明其性质及仍影响核心结论的缺项。没有真实新增实验时，不把重新组织既有结果说成新增实验。
